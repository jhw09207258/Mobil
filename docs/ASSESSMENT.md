# Possion — 기술 점검 및 개선 제안

작성: 2026-07-25 · 기준 커밋: `2a529d7`

이 문서는 추측이 아니라 실제로 확인한 것만 담는다. 각 항목에 **근거**(어디서
확인했는지)를 붙였고, 확인하지 못한 것은 그렇게 표시했다.

## 2. 가장 시급한 것 — 안전망 부재

### 2.1 테스트가 0개 (최우선)

지금까지 이 세션에서만 다음 회귀가 실제로 프로덕션에 나갔다:

- `suggestion$` 플러그인 키 충돌 → **문서 편집기 전체가 죽음** (커밋 `ec2df86`)
- MutationObserver 무한 루프 → **마인드맵 탭 멈춤** (커밋 `dc5d796`)
- 업로드 상태가 리마운트로 소실 → **업로드 중단처럼 보임** (커밋 `2a529d7`)

셋 다 `tsc`와 `npm run build`를 통과했다. 타입 검사로는 절대 잡히지 않는
종류의 버그라서, 지금 구조에서는 **사용자가 유일한 테스트 장치**다.

권장 (비용 대비 효과 순):

1. **에디터 스모크 테스트** — Playwright로 문서/코드/시트/마인드맵을 실제로
   열어보는 것 하나씩. 위 3개 버그 중 2개를 이것만으로 잡았다.
2. **순수 함수 단위 테스트** — `lib/doc-convert.ts`(802줄),
   `lib/mindmap-yjs.ts`, `lib/markdown-parse.ts`. DB 없이 바로 테스트 가능한데
   변환 로직이라 조용히 깨지기 쉽다.
3. **CI** — 위 둘 + `tsc`를 PR마다 실행.

### 2.2 배포 전 검증 단계가 없다

`main`에 push하면 그대로 프로덕션이다. 스테이징 환경이나 프리뷰 확인 절차가
없어서, 위 3개 버그가 전부 사용자에게 먼저 도달했다.

권장: Vercel 프리뷰 배포를 브랜치에 붙이고 `main`은 확인 후 머지. 지금처럼
혼자 빠르게 움직이는 단계라면 최소한 **에디터를 여는 스모크 테스트만이라도**
배포 게이트로 두는 게 좋다.

## 3. 데이터베이스

### 3.1 보안 — 양호

- **ERROR 0건.** RLS는 모든 테이블에 켜져 있고 정책도 일관적이다.
- SECURITY DEFINER 경고 47건은 **의도된 설계**다. 이 프로젝트는 RLS 상호
  재귀를 피하려고 `is_chat_member`, `can_view_object` 같은 헬퍼로 판정을
  모으는데, 각 함수가 내부에서 멤버십을 다시 확인하므로 우회 경로가 없다.
  경고를 끄려고 구조를 바꿀 이유는 없다.
- **실제로 조치할 것 1건**: `auth_leaked_password_protection` 비활성.
  Supabase 대시보드에서 켜면 유출된 비밀번호(HaveIBeenPwned) 사용을 막는다.
  코드 변경 없이 토글 하나 — 승인제 SaaS라면 켜두는 게 맞다.

### 3.2 성능 — 지금은 문제없지만 데이터가 늘면 드러남

| 경고 | 건수 | 영향 |
|---|---|---|
| `auth_rls_initplan` | 6 | `documents/code_files/sheets/mind_maps/files`의 UPDATE·DELETE 정책이 행마다 `auth.uid()`를 재평가. 행이 많아질수록 느려진다. |
| `unindexed_foreign_keys` | 19 | FK에 커버링 인덱스 없음. 특히 `chat_messages_sender_id`, `chat_messages_reply_to_id`는 채팅이 쌓이면 체감된다. |
| `unused_index` | 4 | `sheets_search_idx`, `repositories_owner_idx`, `files_repository_idx`, `sheets_repository_idx` — 쓰인 적 없음(데이터가 적어서일 수 있으니 삭제는 보류 권장). |

`auth_rls_initplan`은 고치기 쉽다 — 정책 안의 `auth.uid()`를
`(select auth.uid())`로 감싸면 끝이다. SELECT 정책들은 이미 그렇게 되어
있는데 UPDATE/DELETE 쪽만 빠져 있다. 마이그레이션 하나로 정리 가능.

### 3.3 `lib/database.types.ts`가 손으로 관리됨

734줄을 수동 유지 중이다. 테이블/RPC를 추가할 때마다 여기도 고쳐야 하고,
빠뜨리면 `supabase.rpc()`가 타입 에러를 낸다(이번 0048 작업에서도 직접
수정했다). Supabase CLI의 `gen types`로 자동 생성하면 이 클래스의 실수가
사라진다.

## 4. 프론트엔드

### 4.1 `chat-shell.tsx` 1,546줄

단일 파일에 목록·스레드·컴포저·이모지/첨부/멘션 메뉴·편집·답장·공감·
읽음표시·타이핑·폴링이 전부 들어 있다. 이번에 공감/답장을 넣을 때도 수정
지점을 찾는 데 시간이 걸렸고, 앞으로 이 파일을 건드릴 때마다 회귀 위험이
커진다. 컴포저 / 메시지 목록 / 대화 목록 정도로 나누는 것을 권장.

### 4.2 번들 크기

| 라우트 | First Load JS |
|---|---|
| `/code/[id]` | 207 kB |
| `/chat` | 182 kB |
| `/files` | 181 kB |
| `/settings` | 173 kB |

CodeMirror·fortune-sheet·mind-elixir가 무거운 건 불가피하지만, 편집기는
이미 `*-loader.tsx`로 분리되어 있으니 라우트 진입 시점이 아니라 **탭을 실제로
열 때** 로드되는지 한 번 확인해볼 가치가 있다.

### 4.3 모바일

이번에 오버플로 3건(공유 ID, 도넛 차트, 검색 드롭다운)을 고쳤다. 다만 이건
전부 CSS를 읽어서 추론한 것이고 **실제 기기 렌더링으로 검증하지 못했다.**
모바일 뷰포트 스크린샷 테스트가 있으면 이런 걸 사람이 발견하기 전에 잡는다.

### 4.4 파티클 배경의 비용

로그인 화면은 프레임마다 `fillRect`를 30,000번(120 strands × 250 points),
대시보드는 9,800번 호출한다. 데스크톱에서는 문제없지만 저사양 폰에서는
발열·배터리 소모가 크다. 기기 성능이나 `prefers-reduced-motion`에 따라
밀도를 낮추는 것을 권장.

## 5. 알려진 미해결 문제

### 5.1 Big Brother(AI)가 프로덕션에서 동작하지 않음

`integrate.api.nvidia.com` 호출이 Vercel(icn1)에서 30초 넘게 멈춘다. 로컬
한국 IP에서는 정상이라 네트워크 경로 문제로 보인다. **임베딩도 같은 키를
쓰므로 시맨틱 검색도 프로덕션에서는 어휘 검색으로만 동작한다.**

선택지: (a) 한국 리전 프록시를 두거나, (b) 리전 제약이 덜한 모델
제공자로 바꾸거나, (c) AI 기능을 데스크톱 앱 전용으로 한정.

### 5.2 업로드의 남은 제약

- 탭을 닫거나 새로고침하면 중단된다(브라우저 제약, `beforeunload` 경고만 가능).
- 파일은 **한 번에 하나씩** 순차 업로드된다.
- **클라이언트에 크기 사전 검사가 없다.** 서버 버킷 한도는 100MB인데
  (`0034_tighten_object_metadata_and_storage.sql`), 그보다 큰 파일을 고르면
  다 올린 뒤에야 실패한다. 다른 업로드 경로(아바타 5MB, 문서 미디어 50MB,
  채팅 사진 10MB)에는 사전 검사가 있는데 저장소 업로드만 빠져 있다 —
  **바로 고칠 수 있는 항목.**

### 5.3 삭제가 영구적

문서·파일 삭제에 휴지통이 없다. 협업 도구에서 실수로 지운 항목을 되돌릴 수
없는 건 위험하다. `deleted_at` 컬럼 + 30일 보관 정도면 충분하다.

## 6. 기능 제안 (우선순위 순)

**바로 효과가 큰 것**

1. **휴지통 / 소프트 삭제** — 위 5.3.
2. **문서 댓글·주석** — 이미 `document_activity`로 누가 언제 고쳤는지는
   기록한다. 협업 편집기에서 다음으로 필요한 건 "이 문단에 대한 대화"다.
3. **버전 히스토리 복원** — Yjs 상태를 이미 저장하고 있으므로 스냅샷을
   주기적으로 남기면 특정 시점으로 되돌리기가 가능하다.
4. **저장소 업로드 크기 사전 검사** — 위 5.2, 몇 줄이면 된다.

**그 다음**

5. **문서 목차(TOC)** — 제목 구조가 이미 있으니 사이드 패널로 뽑기 쉽다.
6. **전체 검색 필터** — 현재는 키워드/태그만. 종류·소유자·기간 필터 추가.
7. **알림 센터** — 지금은 채팅 토스트가 전부다. 공유·멘션·승인 요청이
   쌓이는 곳이 없다.
8. **오프라인 편집** — Yjs를 이미 쓰므로 IndexedDB 퍼시스턴스를 붙이면
   구조적으로 자연스럽다.

**보안**

9. **유출 비밀번호 차단 켜기** (3.1) — 토글 하나.
10. **2FA** — 승인제 + 관리자 콘솔이 있는 만큼 관리자 계정만이라도.
11. **속도 제한** — 로그인·초대·업로드에 rate limit이 보이지 않는다.

## 7. 요약

구조 자체는 견고하다. RLS 설계, SECURITY DEFINER로 재귀를 끊는 방식, Yjs
협업 전송 계층, 브로드캐스트 인가 모델은 잘 잡혀 있고 보안 ERROR도 0건이다.

**가장 큰 위험은 기능이 아니라 검증 부재다.** 하루에 프로덕션 회귀 3건이
났고 전부 타입 검사를 통과했다. 새 기능보다 먼저 스모크 테스트 몇 개와
배포 게이트를 두는 것이, 지금 이 프로젝트에 가장 값어치 있는 투자다.
